# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm install            # this repo is npm-locked (package-lock.json), not pnpm
npm run dev            # react-router dev + @cloudflare/vite-plugin (workerd runtime, port 5173)
npm run typecheck      # wrangler types && react-router typegen && tsc -b  <- the only real check
npm run build          # react-router build
npm run preview        # build + vite preview
npm run deploy         # build + wrangler deploy
```

`worker-configuration.d.ts` is generated by `wrangler types` (via `npm run cf-typegen`) and is
gitignored. A fresh clone will not typecheck until it exists, so run `npm run typecheck` (which
regenerates it) rather than bare `tsc`.

There is **no test framework and no linter** in this repo. "Verified" means `npm run typecheck`
passes plus an actual exercise of the path (send/receive an email, hit the endpoint).

Local secrets go in `.dev.vars` (see `.dev.vars.example`): `POLICY_AUD`, `TEAM_DOMAIN`.
Access JWT validation is skipped when `import.meta.env.DEV`, and **fails closed** otherwise.

Note `send_email` is bound with `"remote": true` in `wrangler.jsonc` — outbound sends from
local dev hit the real Cloudflare Email Service and deliver real mail.

## Architecture

Single Cloudflare Worker (`workers/app.ts`) serving four surfaces off one Hono app, in this
middleware order — order matters, the React Router catch-all swallows anything registered later:

1. Cloudflare Access JWT middleware (`jose`, skipped in DEV)
2. `/mcp` and `/mcp/*` → `EmailMCP.serve()`
3. `/api/v1/*` → the API app from `workers/index.ts`
4. `/agents/*` → `routeAgentRequest()` (WebSocket to `EmailAgent`)
5. `*` → React Router SSR handler

The default export also exposes an `email()` handler for Cloudflare Email Routing inbound mail.

### Storage model

- **One Durable Object per mailbox.** `MailboxDO` id = `idFromName(mailboxId)` where `mailboxId`
  *is the email address* (lowercased). All email/folder/attachment rows live in that DO's SQLite,
  accessed with Drizzle (`workers/db/schema.ts`).
- **R2 (`BUCKET`) is the mailbox registry and blob store.** `mailboxes/{email}.json` holds per-mailbox
  settings (including `agentSystemPrompt`); its *existence* is what makes a mailbox "exist" —
  `requireMailbox` middleware and the MCP tools both `head()` that key before touching the DO.
  Attachments live at `attachments/{emailId}/{attachmentId}/{filename}`.
- **DO schema changes go in `workers/durableObject/migrations.ts`**, appended to `mailboxMigrations`
  as a new `{name, sql}` entry. The runner tracks applied names in a `d1_migrations` table and runs
  on every DO construction. The DO runtime forbids SQL-level `BEGIN TRANSACTION`; the `txn()` helper
  wraps SQL and the runner strips BEGIN/COMMIT and uses `storage.transactionSync()` instead. Keep
  `workers/db/schema.ts` in sync by hand — Drizzle is used only as a query builder, not for migrations.

### Three consumers, one tool layer

`workers/lib/tools.ts` holds all email business logic as plain `toolX(env, mailboxId, params)`
functions. Three callers wrap it, and a change to behaviour belongs in `tools.ts`, not in a wrapper:

- `workers/agent/index.ts` (`EmailAgent extends AIChatAgent`) — the in-app side panel. Wraps tools
  via `defineTool()` (AI SDK v6 overloads are avoided by building the plain object). **Draft-only:
  it deliberately has no send tool.**
- `workers/mcp/index.ts` (`EmailMCP extends McpAgent`) — external clients over `/mcp`. Has the same
  tools *plus* `send_reply`/`send_email`, and takes `mailboxId` as a tool parameter.
- `workers/index.ts` / `workers/routes/reply-forward.ts` — the REST API the SPA calls.

### Agent behaviour

- System prompt: `DEFAULT_SYSTEM_PROMPT` in `workers/agent/index.ts`, overridable per mailbox via
  `agentSystemPrompt` in the R2 settings JSON (edited from the Settings route).
- Chat model is `@cf/moonshotai/kimi-k2.5` via `workers-ai-provider`, `stopWhen: stepCountIs(5)`.
- Auto-draft: inbound mail → `receiveEmail()` stores the email, then `ctx.waitUntil()` POSTs to the
  agent DO at `/onNewEmail`, intercepted in `EmailAgent.onRequest`. The email body *and* the whole
  thread are pre-read and screened by `isPromptInjection()` (`workers/lib/ai.ts`,
  `@cf/meta/llama-3.1-8b-instruct-fast`) which **fails closed** — scanner errors skip the auto-draft.
- Draft bodies pass through `verifyDraft()` (`@cf/meta/llama-4-scout-17b-16e-instruct`) to strip
  agent meta-commentary, with a >50%-shrinkage bailout back to the original.

### Threading

Threads are keyed by `thread_id`, derived (in `receiveEmail`) from `References[0]` → `In-Reply-To`
→ own id, with a subject-normalisation fallback (`findThreadBySubject`, `NORMALIZED_SUBJECT_SQL`
strips Re:/Fwd:/AW:/WG:/Réf:/SV:). Outbound threading headers come from `buildReferencesChain()` +
`buildThreadingHeaders()` in `workers/lib/email-helpers.ts`. Note `email_references` is stored as a
JSON-encoded array in a TEXT column.

### Security boundaries

- Cloudflare Access is the **single trust boundary**. There is no per-mailbox authorization: anyone
  past the Access policy — including anything connected to `/mcp` — can operate on every mailbox.
- `validateSender()` forces the From address to equal the mailbox id on every outbound path.
- Per-mailbox send rate limit lives in `MailboxDO.checkSendRateLimit()`: 20/hour, 100/day, counted
  from rows in the `sent` folder.
- `EMAIL_ADDRESSES` in `wrangler.jsonc` is an allowlist for both mailbox creation and inbound
  routing; empty array means "any address on `DOMAINS`".

### Frontend

React Router v7 in SSR mode (`app/routes.ts`), Kumo components, Tailwind v4 via the Vite plugin.
Server state is TanStack Query only — keys are centralised in `app/queries/keys.ts` and every fetch
goes through `app/services/api.ts` (typed `ApiError`, 30s timeout, no retry on 4xx). Client-only UI
state (selected email, compose panel, agent panel) lives in the Zustand store `app/hooks/useUIStore.ts`.
The agent panel imports `agents/react` and `@cloudflare/ai-chat/react` **lazily** in
`app/components/AgentPanel.tsx` — they are not SSR-safe, so keep them behind that dynamic import.
`~/*` maps to `app/*`; `shared/` is imported by both the Worker and the SPA (folder ids, date fmt).
